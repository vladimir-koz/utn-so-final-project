### **💡 Verdadero o Falso**

**1️⃣ Los contenedores Docker comparten el kernel de la máquina host.** VERDADERO
Los contenedores no tienen su propio sistema operativo como las máquinas virtuales, sino que comparten el kernel del host, por eso son más livianos y rápidos.

**2️⃣ Solo puedes ejecutar un contenedor a la vez usando Docker.** FALSO
Se pueden correr múltiples contenedores al mismo tiempo ya que con docker-compose podés levantar varios servicios coordinados, como hice en el trabajo.

**3️⃣ En un `docker-compose.yml`, la etiqueta `depends_on` asegura que un servicio se inicie antes que otro.** VERDADERO
Indica el orden de arranque (por ejemplo, que el backend espere a la base), aunque no garantiza que esté “listo”, pero sí que se inicie antes.

**4️⃣ Los contenedores creados a partir de la misma imagen siempre tendrán los mismos datos dentro por defecto.** FALSO
Aunque la imagen sea la misma, los contenedores pueden tener datos distintos si usan volúmenes, variables de entorno o archivos montados.

**5️⃣ Nginx puede usarse en un contenedor Docker para servir archivos estáticos del frontend y hacer proxy inverso de peticiones a la API.** VERDADERO
Eso es exactamente lo que hice en el proyecto con Nginx sirviendo HTML y redirigiendo /api o /greet al backend.

### **✍️ Respuesta Corta**

**1️⃣ ¿Cuál es la diferencia entre un contenedor y una imagen en Docker?**
    Una imagen es una plantilla inmutable que contiene todo lo necesario para ejecutar una aplicación (código, dependencias, configuración).
    Un contenedor es una instancia en ejecución de esa imagen, con su propio estado y entorno.

**2️⃣ ¿Para qué se utilizan volúmenes en Docker?**
    Los volúmenes se usan para guardar datos persistentes fuera del contenedor, permitiendo que no se pierdan al reiniciarlo o eliminarlo.
    También permiten compartir datos entre el host y el contenedor, o entre contenedores.

**3️⃣ ¿Qué hace la instrucción `EXPOSE` en un Dockerfile?**
    Indica qué puerto escucha la aplicación dentro del contenedor.
    No publica el puerto automáticamente, pero sirve como documentación y guía para usar ports en Docker Compose o -p en docker run.


**4️⃣ Escribe un beneficio de usar Docker en tus proyectos.**
    Docker permite que una aplicación se ejecute igual en cualquier entorno, evitando errores por diferencias de versiones o configuraciones en distintas computadoras.

**5️⃣ ¿Cuál es el propósito de usar Nginx en tu proyecto Docker?**
    Nginx se usó para servir los archivos del frontend (HTML, CSS, JS) y como proxy inverso para redirigir peticiones a la API del backend, todo desde un mismo punto de acceso (localhost).
